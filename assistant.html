How it works

A text from my phone
↓
The bot
A small always-on server. Replies to quick texts itself, decides what kind of job each request is, and enforces every rule.
↓
Plain code
To-dos, time tracking, reminders and marking mail read. No model runs, so these cost nothing.
Agents on request
One short session per job: a quick lookup, an email draft, or open-ended work on a cloud computer.
Agents on a timer
A heartbeat that decides whether anything deserves a text, an inbox watch, and recipes I set up by text.
↓
What agents can reach
Their own memory, the web, a hosted browser signed in to one read-only site, and mail and spreadsheet tools the bot hands out one call at a time.
What only the bot can do
Send an email, after I text yes to the exact draft. Hold the logins. Stop a job at its cap and pause everything at the daily limit.

The agents

Worker

Claude Opus 5.5

The general worker for anything that needs judgment or several steps: research, writing, building files. Has a cloud sandbox, the web, the browser and its own memory.

Lookup

Claude Haiku 5.5

Read-only quick answers, such as what is due this week or what is in the inbox. It can name mail to mark read, but the bot does the marking.

Email writer

Claude Sonnet 5.5

Writes every first draft with only the email tools and my writing rules. It can save a draft and nothing more.

Email writer, second opinion

Claude Opus 5.5

The same slim writer on a bigger model, used only when I text back asking for a redo.

Heartbeat

Claude Haiku 5.5

Wakes on a timer, reads a snapshot the bot prepares with plain code, and decides whether anything deserves a text. Most runs the answer is no.

Inbox watch

Claude Haiku 5.5

Sorts new mail. The bot checks for new mail with plain code first, so no model runs when nothing arrived.

Recipe runner

Claude Haiku 5.5

Runs the scheduled jobs I set up by text and texts me the result. Limited to a fixed number of tool calls per run.

Skill writer

Claude Sonnet 5.5 · no tools

After a long or corrected job it drafts a short how-to for next time. It never sees what a tool or an email returned, and the bot refuses any how-to that touches a rule.

What it does

  • Texting first. Everything happens over iMessage. A tapback is a full answer when nothing more needs saying.
  • The right model for the job. The bot picks the cheapest agent that can do each job, and uses no model at all when plain code will do.
  • Nothing leaves without a yes. No agent has a send tool. A draft is shown to me word for word, checked again before sending, and only goes out after my own text says yes.
  • Spending caps in code. Every job has a cap, there is a daily limit that pauses new work, and I get a text when either is hit.
  • Recipes by text. I describe a scheduled job in a text and it is live, with a limit on how many there can be and how often they run.
  • Skills it writes itself. How-tos saved from jobs that took many steps or that I corrected, so the next one goes faster and my way.
  • Memory. One store it can write to and one read-only store of facts and rules.
  • A browser as a swappable tool. One hosted browser today, a machine at home later, with no change to the agents.
